Le projet en une minute

Ghost est un assistant visible qui travaille avec vous. Il regarde votre écran, uniquement dans les outils que vous autorisez, repère une tâche que vous répétez et vous propose : « Je m'en occupe ? ». Si vous dites oui, des agents H Company prennent la main sous vos yeux, clic après clic, et chaque action est vérifiée.

L'exemple de la démo : Sophie est office manager chez Atelier Nova, une PME de 50 personnes. Préparer l'arrivée d'un nouveau salarié lui prend environ 2 heures dans plusieurs outils. Un oubli et le nouveau arrive sans accès ni badge. Sophie prépare l'arrivée de Léa, développeuse. Quand l'arrivée de Karim, commercial, apparaît à l'écran, Ghost la lit et dit : « Je prépare l'onboarding de Karim comme pour Léa ? ». Sophie dit oui. Trois agents H partent en même temps : l'un crée la fiche, les accès et le badge, l'autre écrit au bon canal et demande un parrain, le troisième prépare le wiki. Un tableau se coche en direct.

Pourquoi cette nouvelle direction

Les professeurs ont dit : l'idée de base est bonne, mais H Company n'agit qu'à la fin (clic « Prouver »), et le risque est une note nulle sur l'usage de l'agent. Le jury note 30 % sur l'excellence technique et l'API des agents, et son critère n°1 est une démo live avec l'agent qui tourne. Ghost doit donc montrer H à trois moments :

1H observe

La pastille avec notre logo reste affichée. Holo, le modèle de lecture d'écran de H, lit les captures.

2H propose

« J'ai vu que tu refais la même chose, je m'en occupe ? » Ni liste fixe, ni écran de résultats à la fin.

3H agit

Après accord, trois agents travaillent en direct. On voit l'écran, on voit le tableau se cocher, on voit la vérification.

Les décisions de l'interview

  • Vocal facultatif : la démo fonctionne sans, avec un bouton visible.
  • Source principale : l'enregistrement d'écran. Intervention 10 s en général, 30 s au maximum après la reconnaissance.
  • Les agents H agissent dans le navigateur hébergé de H, avec vue en direct. Le contrôle de l'ordinateur local, WhatsApp, etc. sont en roadmap. L'écran « J'ai besoin de ton Chrome, tu m'autorises ? » existe dans notre portail et décide quels espaces l'agent peut utiliser.
  • Trois agents en parallèle, plan B : vidéo d'un vrai run complet filmé avant.
  • Ce qu'on garde honnête : aucune donnée réelle, tout rejeu annoncé, aucun succès simulé, une action n'est comptée que si elle est vérifiée dans la base.
  • Mémoire de session (nouveau) : Binta propose d'enregistrer avant la démo quelques minutes de vraies sessions pour donner du contexte à l'agent, puis de refaire le geste en quelques secondes en direct. C'est honnête si on le dit : « mémoire d'une session précédente, réelle, enregistrée avant ». La détection pendant la démo reste réelle.
  • Pas de région UE obligatoire, trois garanties de confidentialité à vérifier avant d'être annoncées (captures limitées aux outils cochés, pastille et pause toujours visibles, images non conservées).

Le nettoyage GitHub, étape par étape (Binta)

Je ne pousse rien. Tu lances ces commandes toi-même, ou tu me dis « vas-y » pour chaque push. Si GitHub refuse un push direct sur main, passe par une branche et une PR.
  1. Prévenir le groupe : « Ne poussez rien sur main jusqu'à nouvel ordre. »
  2. Se mettre à jour : git checkout main puis git pull
  3. Créer l'archive : git branch archive-avant-new-era puis git push origin archive-avant-new-era. Tout l'ancien projet reste là, intact.
  4. Copier à part (hors dépôt) ce que tu veux garder : binta-cpo/design (charte, logo) et les fichiers de binta-cpo/specs.
  5. Retirer les anciens dossiers : git rm -r alejandro-cto assel-ceo binta-cpo commun henriquet-cdo omar-caio vladimir-cao (vérifie la liste avec ls d'abord ; garde .github si elle contient la CI).
  6. Recréer le nouveau dossier et le README : ghost-new-era/README.md avec le titre « GHOST New Era », ce que fait le projet, comment le tester, un lien vers l'archive. Recopier la charte et les docs dans ghost-new-era/docs.
  7. Commit et push : git add -A, git commit -m "GHOST New Era : nouvelle base, ancien projet archivé", git push origin main.
  8. Prévenir le groupe : « main est propre. Faites git pull puis créez votre branche. » Les anciennes PR ouvertes (#62, #63, #65) sont à fermer, leur code reste dans l'archive.
